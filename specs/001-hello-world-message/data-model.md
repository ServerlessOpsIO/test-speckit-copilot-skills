# Data Model: Hello World Message Delivery

## Overview

The feature is modeled as a Step Functions execution contract with deterministic output payloads for success and fallback paths.

## Entities

### 1. GreetingExecutionInput

Represents the input payload when starting a state machine execution.

| Field | Type | Required | Validation | Description |
|---|---|---|---|---|
| `forceFallback` | boolean | No | Defaults to `false` when omitted | Simulates repeated temporary delivery failure for fallback validation; the retry is still attempted |
| `requestId` | string | No | Non-empty if provided | Optional correlation identifier for troubleshooting |

### 2. GreetingResult

Represents the logical result generated by the workflow.

| Field | Type | Required | Validation | Description |
|---|---|---|---|---|
| `status` | string | Yes | Enum: `SUCCESS` \| `FALLBACK` | Result state emitted by workflow |
| `message` | string | Yes | If `SUCCESS`, must equal exactly `"Hello, World!"` | User-readable message available in execution output or logs |
| `retryable` | boolean | Yes | `false` for success, `true` for fallback | Indicates retry recommendation |

### 3. GreetingExecutionOutput

Top-level output payload from Step Functions execution.

| Field | Type | Required | Validation | Description |
|---|---|---|---|---|
| `result` | object (`GreetingResult`) | Yes | Must match `GreetingResult` schema | Final greeting payload |
| `executionContext` | object | No | May include execution metadata | Optional context for observability |

## Relationships

- `GreetingExecutionOutput.result` references exactly one `GreetingResult`.
- `GreetingExecutionInput.forceFallback` simulates temporary delivery failures for validation; after one retry, those failures determine `GreetingResult.status`.

## State Transitions

1. **Start** → read `GreetingExecutionInput`
2. **Branch**:
   - Successful delivery → emit `SUCCESS` with `"Hello, World!"`
   - Temporary delivery failure → retry once automatically
   - Delivery still fails after the retry → emit `FALLBACK` with retry guidance
3. **Finish** → produce `GreetingExecutionOutput` and expose via execution logs

## Invariants

- Successful executions always return exact message `"Hello, World!"`.
- Every execution returns either `SUCCESS` or `FALLBACK`; never blank output.
- The execution output contains the result; CloudWatch execution logs include execution data for additional visibility.
- A temporary delivery failure is retried exactly once before fallback is returned.
